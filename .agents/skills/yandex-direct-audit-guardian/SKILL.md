# 🛡️ Yandex Direct Audit Guardian

Специализированный инженерный скилл для проведения глубокого аудита, оценки качества и непрерывной оптимизации рекламных кампаний в **Яндекс.Директ** (API v5) для платформы OmniSMM / SMMplan.

Базируется на открытой методологии аудита **Silverov/yandex-direct-skill** и лучших практиках performance-маркетинга Рунета 2025–2026 гг.

---

## 🎯 Когда активировать скилл
* При запросах на аудит действующего рекламного кабинета Яндекс.Директ;
* Перед запуском новых кампаний для предрелизной верификации настроек;
* При перерасходе бюджета или аномальном росте стоимости лида (CPA / CPL);
* Для регулярного еженедельного скоринга эффективности кампаний (A–F Audit);
* При необходимости оптимизации ставок и отсечения нерентабельных фраз по правилу **3x Kill Rule**.

---

## 🏗️ 55 контрольных точек аудита (6 категорий)

Скилл анализирует кампании по 6 ключевым блокам, формируя взвешенный балл здоровья кабинета от **A** (отлично) до **F** (критично):

### 1. Настройки веб-аналитики и трекинга (Вес: 25%)
- [ ] Счетчики Яндекс.Метрики привязаны ко всем кампаниям без исключений;
- [ ] Разметка ссылок: 100% объявлений и быстрых ссылок содержат динамические UTM-метки (`utm_source=yandex&utm_medium=cpc&utm_campaign={campaign_id}&utm_content={ad_id}&utm_term={keyword}`);
- [ ] В Метрике настроены электронная коммерция (e-commerce) или передача дохода по целям;
- [ ] Настроены составные цели: микро-конверсии (регистрация, выбор услуги) и макро-конверсии (пополнение баланса, оплата заказа);
- [ ] Активирован мониторинг доступности сайта (автоостановка рекламы при падении сервера).

### 2. Структура аккаунта и семантика (Вес: 20%)
- [ ] Строгое разделение: **Поиск** и **РСЯ** вынесены в отдельные кампании (запрещены смешанные кампании);
- [ ] Кампании брендового спроса конкурентов изолированы в отдельную структуру;
- [ ] Наличие списков кросс-минусовки между группами объявлений (защита от каннибализации);
- [ ] Отсутствие статус-бага «Мало показов» у низкочастотных групп (кластеризация фраз);
- [ ] Использование кавычек `"` и скобок `[]` для фиксации словоформ в дорогих горячих ключах.

### 3. Качество и релевантность объявлений (Вес: 20%)
- [ ] В каждой группе объявлений создано $\ge 2$–3 текстово-графических вариантов для сплит-теста;
- [ ] Заголовок 1 содержит точное или синонимичное вхождение ключевой фразы (подсветка жирным в выдаче);
- [ ] Заполнен Заголовок 2 (до 30 символов) с конкретным оффером или УТП;
- [ ] Заполнены все 8 быстрых ссылок с подробными описаниями (до 66 символов);
- [ ] Заполнены 4 промо-уточнения (до 25 символов);
- [ ] Заполнена виртуальная визитка (vCard / контактная информация);
- [ ] Заполнена отображаемая ссылка (до 20 символов).

### 4. Бюджетный пейсинг и управление ставками (Вес: 15%)
- [ ] Установлены жесткие дневные/недельные лимиты бюджета на уровне каждой кампании;
- [ ] Достаточность бюджета: недельный бюджет превышает целевой CPA минимум в **10 раз** для успешного обучения автостратегий;
- [ ] Отсутствие эффекта "Budget Exhaustion" (преждевременная остановка кампании в первой половине дня);
- [ ] Корректировки ставок по устройствам: разделение Mobile / Desktop в соответствии с конверсией посадочной страницы.

### 5. Безопасность и соответствие правилам модерации (Вес: 10%)
- [ ] Полное соответствие **пункту 15 Требований Яндекса** (отсутствие слов «накрутка», «боты» в текстах объявлений);
- [ ] Белое позиционирование: продвижение, PR, привлечение аудитории, B2B API, SMM-софт;
- [ ] 0 объявлений со статусом «Отклонено модератором».

### 6. Защита от нецелевого трафика и скликивания (Вес: 10%)
- [ ] Единый глобальный список минус-слов на уровне кампании ($\ge 50$ общих стоп-слов);
- [ ] Регулярная минусовка мусорных запросов из отчета «Поисковые запросы»;
- [ ] Исключение площадок РСЯ с CTR $> 8\%$ при 0 конверсий (мобильный фрод).

## ⚡ Жесткие правила оптимизации (Quality Gates)

### 🛑 1. "3x Kill Rule" (Отсечение нерентабельных фраз и площадок)
```text
ЕСЛИ расход по ключевой фразе или площадке РСЯ >= 3 * Target_CPA
И число конверсий == 0
ТОГДА:
  - На Поиске: немедленная остановка фразы или снижение ставки до минимальной (0.3–0.9 ₽);
  - В РСЯ: немедленное добавление площадки в список запрещенных (минус-площадки).
```

### 📉 2. "Low-CTR Pruning Rule" (Чистка кликабельности)
```text
ЕСЛИ на Поиске показов >= 300 И CTR < 3.5%
ТОГДА:
  - Переписать Заголовок 1 под точное вхождение поискового запроса;
  - Проверить отчет по поисковым фразам на наличие информационного мусора.
```

### 💰 3. "Budget Pacing Invariant" (Контроль расхода)
```text
ЕСЛИ кампания расходует > 60% дневного лимита до 12:00 дня
ТОГДА:
  - Снизить базовую ставку на 20-30% или сузить таргетинг;
  - Проверить наличие широкого автотаргетинга без минус-слов.
```

## 📊 Матрица шкалы здоровья кампании (Direct Health Score)

| Оценка | Процент проверок | Вердикт | Действие |
| :---: | :---: | :--- | :--- |
| **A** | **90 – 100%** | Отличное состояние, высокая конверсия | Масштабирование бюджета, расширение LAL |
| **B** | **80 – 89%** | Хорошее состояние, мелкие недочеты | Добавление недостающих быстрых ссылок, уточнение ставок |
| **C** | **65 – 79%** | Среднее состояние, утечки бюджета | Очистка минус-слов, разделение Поиска и РСЯ |
| **D** | **50 – 64%** | Критическое состояние, потеря денег | Применение 3x Kill Rule, перенастройка целей Метрики |
| **F** | **< 50%** | Слив бюджета | Немедленная остановка кампаний до полного исправления |

## 🛠️ Справочные команды аудитора

* `/direct audit` — запуск полного цикла проверки кампаний по 55 пунктам с выводом итогового грейда (A–F) и списка критических ошибок.
* `/direct budget` — аудит пейсинга бюджетов, прогноз исчерпания средств до конца месяца и проверка недельного лимита для автостратегий.
* `/direct optimize` — поиск фраз-кандидатов под правило 3x Kill Rule и генерация пакета изменений.
* `/direct negative` — перекрестный анализ отчета поисковых запросов и формирование новых минус-слов.
