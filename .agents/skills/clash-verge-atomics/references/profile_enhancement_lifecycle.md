# Жизненный Цикл Профилей и Profile Enhancement в Clash Verge Rev

## 1. Проблема Уязвимости Удаленных Подписок

Удаленные подписки (Remote Profiles, e.g. Quattro Cloud) распространяются провайдерами через ссылки вида `https://auth.quattro-cloud.ru/...`.
В `profiles.yaml` для них задан интервал автообновления:
```yaml
- uid: RKVVdvN9vPR5
  type: remote
  url: https://auth.quattro-cloud.ru/...
  option:
    update_interval: 60
    allow_auto_update: true
```

Каждые 60 минут клиент Clash Verge выполняет фоновый HTTP GET запрос и перезаписывает файл `profiles/RKVVdvN9vPR5.yaml`.
Если администратор вручную впишет правила в этот файл, **через 60 минут они будут уничтожены**.

## 2. Архитектура Profile Enhancement

Clash Verge Rev реализует 3-уровневый конвейер сборки (Pipeline), накладывающий локальные изменения поверх базовой подписки.

```
┌────────────────────────────────────────┐
│ 1. Базовый профиль (<uid>.yaml)        │ (Перезаписывается провайдером)
└───────────────────┬────────────────────┘
                    │
                    ▼
┌────────────────────────────────────────┐
│ 2. Шаблон слияния (<merge_uid>.yaml)   │ (Локальный файл, персистентный)
│    mode: rule                          │ Рекурсивный Deep Merge корневых ключей
└───────────────────┬────────────────────┘
                    │
                    ▼
┌────────────────────────────────────────┐
│ 3. Шаблон правил (<rules_uid>.yaml)    │ (Локальный файл, персистентный)
│    prepend: [...]                      │ Вставка правил на вершину стека
│    append: [...]                       │ Вставка правил в хвост перед MATCH
│    delete: [...]                       │ Удаление правил провайдера
└───────────────────┬────────────────────┘
                    │
                    ▼
┌────────────────────────────────────────┐
│ 4. JavaScript Script (<script_uid>.js) │ (Опциональный скрипт модификации DOM)
│    function main(config) { ... }       │
└───────────────────┬────────────────────┘
                    │
                    ▼
┌────────────────────────────────────────┐
│ Итоговый clash-verge.yaml              │ Передается ядру verge-mihomo
└────────────────────────────────────────┘
```

## 3. Режимы Маршрутизации и Их Влияние на Pipeline

В Clash Verge Rev существуют 4 глобальных режима:

1. **Rule (Рекомендуемый)**:
   - Полная обработка цепочки правил.
   - Падение в `MATCH` только если ни одно правило не сработало.
2. **Global**:
   - Правила **НЕ ВЫЧИСЛЯЮТСЯ**.
   - Весь трафик идет через селектор `GLOBAL`.
3. **Direct**:
   - Правила **НЕ ВЫЧИСЛЯЮТСЯ**.
   - Весь трафик идет мимо прокси через сетевой адаптер хоста.
4. **Script**:
   - Маршрутизация на основе встроенного движка сценариев JavaScript.

### Как заблокировать сброс в `Global` навсегда:
В файле `profiles/mFo3hiyFMILJ.yaml` и `profiles/Merge.yaml` прописать:
```yaml
mode: rule
```
При слиянии эта директива перекроет параметр `mode: global`, пришедший от провайдера подписки.
