# Маршрутизация в Суверенном Периметре РФ (ТСПУ, WAF, DIRECT)

## 1. Специфика Российского Сегмента Сети

При работе через зарубежные VPN и прокси-ноды (Нидерланды, Германия, Испания, США) пользователи в РФ сталкиваются с рядом жестких ограничений:

1. **Геоблокировки российских сервисов**:
   - Государственные порталы (Госуслуги, ФНС, ЕГИССО).
   - Банки (Сбер, Т-Банк, Альфа-Банк) блокируют авторизацию с иностранных IP-адресов или включают агрессивную Cloudflare/Qrator капчу.
   - B2B-сервисы и админ-панели (например, `panel.smmtoolbox.ru`, `happydesk.ru`) возвращают ошибку таймаута TCP SYN (`context deadline exceeded` / `i/o timeout`), защищаясь от зарубежных DDoS-атак.

2. **Замедление и блокировки ТСПУ (ТСПУ РКН)**:
   - Внешние VLESS/Shadowsocks туннели подвергаются активному зондированию и DPI-фильтрации.
   - Если внутренний трафик к сайтам РФ пускать через внешний туннель, возникает «двойной кросс-бордер петлевой маршрут» (РФ -> Испания -> РФ), увеличивающий задержку (RTT) со стандартных 5 мс до 150+ мс.

## 2. Архитектура Эталонного Правила для Зоны РФ

Для обеспечения 100% прямого и быстрого доступа к российским сервисам в блок `prepend:` файла правил вносятся 4 эшелона защиты:

```yaml
prepend:
  # Эшелон 1: Точечные критические хосты (Приоритет 1)
  - DOMAIN,panel.smmtoolbox.ru,DIRECT
  - DOMAIN,primelike.happydesk.ru,DIRECT

  # Эшелон 2: Доменные суффиксы инфраструктуры
  - DOMAIN-SUFFIX,smmtoolbox.ru,DIRECT
  - DOMAIN-SUFFIX,happydesk.ru,DIRECT

  # Эшелон 3: Национальные доменные зоны высшего уровня (TLD)
  - DOMAIN-SUFFIX,ru,DIRECT
  - DOMAIN-SUFFIX,su,DIRECT
  - DOMAIN-SUFFIX,xn--p1ai,DIRECT       # .рф (IDN Punycode)
  - DOMAIN-SUFFIX,xn--80aswg,DIRECT     # .сайт
  - DOMAIN-SUFFIX,xn--80asehdb,DIRECT   # .онлайн

  # Эшелон 4: Базы Geosite и GeoIP с защитой DNS
  - GEOSITE,category-ru,DIRECT
  - GEOIP,RU,DIRECT,no-resolve
```

---

## 3. Критический Нюанс: Флаг `no-resolve`

Почему для `GEOIP,RU,DIRECT` **жизненно необходим** параметр `no-resolve`?

- Без `no-resolve`: Если запрос идет к домену `example.com`, ядро Mihomo ПЕРЕД проверкой правила обязано отправить DNS-запрос, чтобы узнать его IP. Если внешний DNS медленный или заблокирован, все соединения зависают на 2-5 секунд.
- С `no-resolve`: Ядро проверяет правило `GEOIP` ТОЛЬКО если клиент уже обратился по IP-адресу. Если обращение идет по доменному имени, ядро пропускает это правило и переходит к следующему, не тратя время на паразитный резолв.
