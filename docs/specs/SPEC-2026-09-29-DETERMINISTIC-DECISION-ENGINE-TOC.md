# SPEC-2026-09-29-DETERMINISTIC-DECISION-ENGINE-TOC (v1.0)
# Детерминированная Модель Принятия Решений НПУ (TOC POOGI Decision Engine)

> **Стандарт надежности платформы OmniSMM 1.0 (2026)**  
> **Фундаментальный закон:** Вероятностная нейросеть не может быть судьей другой вероятностной нейросети. Арбитраж качества, факта исправления дефекта и соблюдения архитектурных инвариантов осуществляется строго детерминированной моделью принятия решений (Deterministic Decision Engine — DDE) на основе синтаксического анализа (AST), среды выполнения (Runtime TDD) и геометрических измерений браузера (DOM Sensors) с нулевым расходом токенов (Zero-Token Verification) и 100% математической достоверностью.

---

## 1. Контекст и Проблема (TOC Constraint Analysis)

### 1.1. Проблема «Нейронка проверяет нейронку» (Variance Stacking)
При использовании мультиагентного протокола Maker-Checker (Создатель vs Ревизор-LLM) возникают три критических ограничения:
1. **Operating Expense (OE) раздут:** На каждое ревью тратятся тысячи платных токенов LLM (до 15 000 токенов за итерацию).
2. **Throughput (T) замедлен:** Время инспекции кода второй нейросетью составляет от 30 до 60 секунд.
3. **Ложное чувство безопасности (Hallucination Risk):** Нейросеть-ревизор может поверить утверждению «Я всё исправила», пропустить скрытую утечку типов (`any`), не заметить ReDoS или проигнорировать нарушение финансового леджера.

### 1.2. Решение: Детерминированная Модель Принятия Решений НПУ (DDE-2026)
Перенос функции ревизора с субъективной LLM на объективную систему 4 аппаратных сенсоров, дающих строгий бинарный вердикт (`PASS` / `REJECT`) за $< 2$ секунд без расхода токенов.

## 3. Детальные Спецификации Сенсоров

### 3.1. Сенсор 1: AST Method & Invariant Sensor
- **Назначение:** Доказательство того, что нейросеть применила требуемые архитектурные конструкции и не использовала запрещенные антипаттерны.
- **Инварианты проверки:**
  1. `EXACTMATH_BIGINT_GUARD`: В файлах финансового контура (`src/services/financial/`, `src/actions/order/checkout.ts`) запрещены `Math.round(parseFloat(...))` и операции с числами с плавающей точкой в финансовых расчетах. Обязателен вызов `ExactMath.*` или нативного `BigInt`.
  2. `TRANSACTION_ESCAPE_GUARD`: Внутри транзакционных блоков `prisma.$transaction(async (tx) => { ... })` запрещены любые прямые обращения к глобальному экземпляру `db.*`.
  3. `LEDGER_FIRST_GUARD`: Любые операции мутации баланса пользователя (`tx.user.update`, `WalletOps`) обязаны предваряться созданием проводки `tx.ledgerEntry.create`.
  4. `TENANT_ISOLATION_GUARD`: Все входящие вебхуки и системные обработчики обязаны вызывать `runWithTenant` или `runWithTenantBypass`.
  5. `NEXT16_PAGE_SERVER_GUARD`: В файлах `page.tsx` строжайше запрещена директива `"use server"`.

### 3.2. Сенсор 2: Runtime TDD Proof Sensor
- **Назначение:** Объективное подтверждение устранения дефекта средой выполнения.
- **Логика:**
  - Если для задачи был сформирован падающий тест-репродьюсер (Red Phase), сенсор запускает тест и проверяет переход в Green Phase (`exitCode === 0`).
  - Запускаются динамически вычисленные тесты радиуса поражения (Impact Radius) через `resolveImpactedTests()`.
  - Запрещен деплой при наличии хотя бы 1 упавшего ассерта.

### 3.3. Сенсор 3: Static Hygiene & No-Crutch Sensor
- **Назначение:** Предотвращение накопления технического долга и утечек секретов.
- **Критерии вето (Veto Criteria):**
  - Ошибки компилятора TypeScript: $> 0 \to \text{REJECT}$;
  - Утечки секретов/токенов в бандле: $> 0 \to \text{REJECT}$;
  - Использование `any` в измененных строках: $> 0 \to \text{REJECT}$;
  - Подавления типов (`@ts-ignore`, `@ts-expect-error`, `eslint-disable`): $> 0 \to \text{REJECT}$;
  - Заглушки (`// TODO`, `// FIXME`, `// HACK`): $> 0 \to \text{REJECT}$.

### 3.4. Сенсор 4: DOM Geometry & Mobile Ergonomics Sensor
- **Назначение:** Аппаратный контроль пользовательского интерфейса в реальном браузере.
- **Критерии проверки:**
  - $\Delta_{\text{scroll}} = \text{document.body.scrollWidth} - \text{window.innerWidth} \le 0$;
  - Все числовые инпуты `<input type="number">` имеют `inputMode="numeric"`;
  - Микрокнопки и интерактивные элементы имеют габариты $\ge 44\times 44\text{px}$;
  - Консоль браузера свободна от ошибок React 19 Hydration Mismatch.
