# SPEC-2026-09-18: Автоматическое подтверждение Cookie (152-ФЗ) при авторизации (Auth Auto-Consent)

## 1. Контекст и проблема
В соответствии с 152-ФЗ («О персональных данных») на платформе действует баннер согласия с использованием файлов cookie (CookieConsent.tsx).
Однако ранее баннер подключался глобально в RootLayout и отображался в том числе внутри личного кабинета (/dashboard), если пользователь заходил по прямой ссылке, закладке или Magic Link из почты.
При регистрации и входе пользователь **уже акцептует** Условия сервиса и Политику конфиденциальности платформы, поэтому повторный показ баннера в кабинете создаёт избыточный визуальный шум и перекрывает нижнюю панель навигации на мобильных устройствах.

## 2. Архитектурное решение (Вариант 1)
1. **Авто-выдача cookie при создании сессии (createSession в src/lib/session.ts)**:
   - В момент успешной аутентификации (вход по паролю, Magic Link, авто-регистрация при чекауте) сервер вместе с сессионным токеном выставляет cookie cookie_consent=true с параметрами:
     - httpOnly: false (чтобы клиентский JS мог прочитать согласие);
     - maxAge: 31536000 (1 год);
     - path: '/';
     - sameSite: 'lax';
     - secure: process.env.NODE_ENV === 'production'.
2. **Авто-выдача в Route Handler подтверждения входа (src/app/api/auth/verify/route.ts)**:
   - На редирект-ответе Magic Link выставляется cookie_consent=true.
3. **Бесшовный переход для существующих авторизованных пользователей (src/components/common/CookieConsent.tsx)**:
   - Если пользователь находится на маршрутах /dashboard, плашка не отображается (eturn null), а cookie_consent=true автоматически фиксируется в document.cookie и localStorage, предотвращая мерцание.
4. **Сохранение 152-ФЗ на публичных витринах**:
   - На страницах /, /services, /knowledge, /legal/* для неавторизованных посетителей плашка продолжает штатно функционировать.
